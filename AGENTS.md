# AGENTS.md — Mini GTD

Інструкції для будь-якого AI-асистента/агента, що працює в цьому
репозиторії (Claude Code, Cursor, GitHub Copilot, Codex, Windsurf,
Jules, Antigravity тощо). Це дистильована, швидка для читання версія двох
повних документів проєкту — **завжди звіряйся з ними для деталей,
яких тут нема**, і онови їх (і цей файл, якщо структура змінилась)
у тому ж кроці, що й код:

- **[PROJECT_RULES.md](PROJECT_RULES.md)** — правила розробки
  (мова, файли, кольори, обсяг фіч, шар логіки, операційні
  обмеження). Мають пріоритет над будь-якою задачею, що їм
  суперечить.
- **[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)** — повний
  технічний стан: стек, схема БД, усі маршрути, дизайн-токени,
  Edge Functions, розгортання. Оновлюється в тому ж кроці, що й
  код, — не «колись потім».
- **[docs/PRD.md](docs/PRD.md)** — що саме будуємо (продукт).

## Що це за проєкт

Mini GTD — персональний GTD-менеджер задач, українською мовою,
для одного користувача. Vanilla JS (без фреймворків/збірника) +
Supabase (Postgres + Auth + Storage + Edge Functions) + Netlify.

## Правила (PROJECT_RULES.md, повний текст)

1. **Мова інтерфейсу — українська.** Увесь текст, який бачить
   користувач (написи, кнопки, помилки, плейсхолдери) — українською.
   Виняток — три місця, де текст малює не застосунок, а браузер/ОС/
   Google (`window.alert`/`confirm`/`prompt`, нативний `<input
   type="date">`, екран узгодження доступу Google) — на них вплинути
   кодом неможливо.
2. **Не додавати зайвих файлів чи бібліотек без потреби.** Мінімальний
   набір інструментів для поточного кроку, не «про запас».
3. **Кожен компонент — в окремому файлі.** Без «богоподібних» файлів.
4. **Кольори — лише через CSS-змінні.** Ніяких хардкоджених кольорів
   у компонентах. Усі кольори — дизайн-токени в `:root`/
   `:root[data-theme="light"]` (`css/style.css`), скрізь інде —
   лише `var(--...)`.
5. **Не додавати фічі, яких нема в плані.** Реалізується те, що
   описано в задачі чи `docs/PRD.md`. Ідеї «до речі, було б непогано
   ще…» — озвучити окремо, не втілювати одразу.
6. **Бізнес-логіка не живе в UI-компонентах.** Компоненти — лише
   відображення й взаємодія; дані/GTD-правила/збереження стану —
   в `js/store/*.js`.
7. **Операційні обмеження AI-асистента:**
   - **Не пушить у git** (`git push`) і **не виконує SQL** проти
     Supabase (нові файли в `supabase/migrations/`) — обидва рази
     це робить сам розробник вручну.
   - **Може** деплоїти Edge Functions (`supabase functions deploy
     ...`) — не потребує доступу до секретів, не чіпає базу напряму.
   - **Ніколи не бачить і не вводить значення секретів** (bot token,
     service_role key, API-ключі) — лише називає, який секрет
     задати; значення підставляє сам розробник.
   - **Не імітує реальний вхід через Google** (OAuth) — завжди
     робить сам користувач.
   - Архітектурна зміна → одразу в `docs/ARCHITECTURE.md`, в тому ж
     кроці.

## Технологічний стек

- **HTML/CSS/vanilla JS (ES-модулі)** — без збірника, без
  npm/node_modules. Браузер сам розуміє `import`/`export`
  (`<script type="module">`).
- Єдиний виняток — `@supabase/supabase-js`, підключений напряму з
  ESM-CDN (`https://esm.sh/@supabase/supabase-js@2`) в
  `js/lib/supabaseClient.js`.
- **Supabase** (Postgres + Auth + Storage + Edge Functions) — уся
  «серверна» частина; свого бекенду в проєкту немає. RLS
  (`auth.uid() = user_id`) — єдиний захист даних, не секретність
  ключів у `js/config.js` (публічні за задумом).
- **Маршрутизація** — клієнтська, на History API, `js/router.js`,
  без бібліотек-роутерів.
- **Локальний прев'ю** — `python3 scripts/serve.py` (SPA-fallback:
  віддає `index.html` для будь-якого шляху без файлу на диску —
  інакше пряме відкриття `/list/next` дасть 404).
- **Хостинг** — Netlify, автодеплой з `main` на кожен `git push`.
  Кожен push = деплой = кредити (безкоштовна квота) — `netlify.toml`
  скасовує деплой, якщо між пушами змінилась лише документація.

Новий фреймворк/збірник/бібліотека — лише коли складність проєкту
дійсно цього вимагає (правило №2).

## Структура файлів — де що шукати

- `index.html` — єдина точка входу (shell); inline-скрипт у `<head>`
  застосовує тему синхронно до першого рендеру.
- `css/style.css` — **усі** дизайн-токени (`:root` +
  `:root[data-theme="light"]`) + глобальні стилі. Кожен інший
  компонент/сторінка — свій `css/<назва>.css`, підключений в
  `index.html`.
- `js/app.js` — точка входу: `initTheme()` → `initAuth()` → монтує
  навігацію й фон → `initBackground()` → `initRouter()`.
- `js/router.js` — таблиця маршрутів, захист (`protected`), History
  API, плавний перехід між сторінками.
- `js/config.js` — публічні (не секретні) конфіг-значення.
- `js/lib/supabaseClient.js` — єдиний спільний клієнт Supabase.
- `js/store/*.js` — **уся** робота з даними (Supabase-запити,
  бізнес-логіка). Кожен файл — своя область (`taskStore.js`,
  `subtaskStore.js`, `authStore.js`, `themeStore.js` тощо). Функції
  `async`, повертають/кидають — компоненти самі вирішують, як
  показати результат/помилку.
- `js/components/*.js` — один компонент = один файл, названий за
  призначенням. Не знають, звідки беруться дані чи як вони
  зберігаються — лише рендер + колбеки (`onToggleCompleted`,
  `onStatusChange`, `onDelete` тощо) нагору, до сторінки.
- `js/pages/*.js` — одна сторінка = один файл; монтує незмінну
  частину (форму/заголовок) один раз, після кожної дії
  перемальовує лише список/картку (не всю сторінку).
- `supabase/functions/*/index.ts` — Edge Functions (Deno): усе, що
  потребує довіреного сервера (Telegram-вебхук, cron-нагадування,
  проксі до Groq, вебхук стрічки). Спільний код — `_shared/`.
- `supabase/migrations/*.sql` — схема БД + RLS. Файли з датою в назві,
  виконуються по порядку вручну в Supabase SQL Editor (AI не виконує).
- `docs/`, `PROJECT_RULES.md` — джерело правди для архітектури й правил.

## Ключові патерни

**Три різні моделі оновлення UI**, свідомо різні за складністю задачі:
- **Мутації самої задачі** (тег/статус/список/дедлайн/виконано/
  кошик) — сторінка перечитує задачу(і) й перемальовує весь список/
  картку після кожної дії. Просто й надійно для особистого обсягу
  даних.
- **Підзадачі** — `TaskCard.js` сам вантажить/оновлює лише свій
  розділ, без перемальовування картки. Додавання — **Optimistic
  UI** (рядок з'являється одразу, tmp-id підміняється справжнім чи
  прибирається при помилці).
- **Матеріали** — так само самодостатній блок (`MaterialsBlock.js`).

**Обробка помилок** — завжди одна форма: `console.error(err)` для
діагностики (сирий текст Supabase — англійською, не для користувача)
+ фіксований український текст користувачу (`window.alert(...)` для
дій над одним рядком, текст замість вмісту для провалу завантаження
списку). Незворотні дії («Видалити назавжди» тощо) —
`window.confirm()` перед запитом.

**Статус vs. виконано** — `tasks.status`
(`urgent`/`not_urgent`/`daily`/`waiting`/`cancelled`) і
`tasks.completed` (булеве) — окремі поля, одне джерело правди для
dropdown-у в картці (`TaskCard.js`) і колонок дошки `/board`, обидва
шляхи ведуть до `taskStore.changeTaskStatus()`. Псевдо-опція
`"done"` у dropdown-і веде через `completeTask()` (не просто
`setTaskCompleted`) — щоб повторювані задачі коректно клонувались.

**Повторювані задачі** — без фонових завдань/окремої таблиці:
`completeTask()` на задачі з `recurrence` одразу створює нову
задачу на наступну дату, стару лишає виконаною назавжди (історія
повторень). `recurrence_anchor_day` — окреме поле для "рідного дня
місяця" (запобігає постійному застряганню на 28-му після лютого).

**Дизайн-токени й тема** — усі кольори лише в `css/style.css`,
`:root` (темна, за замовчуванням) і `:root[data-theme="light"]`
(світла, перемикається в меню акаунта, `js/store/themeStore.js`,
значення в `localStorage`, не в БД). `--accent-ink` — окремий,
теми-незалежний токен для тексту на суцільній заливці
`--accent`/`--accent-gradient` — **завжди звіряй**, що новий
елемент з кольоровим фоном бере правильний токен тексту, інакше
одна з тем дасть нечитабельний контраст.

## Часті пастки (уже були баги — не повторювати)

- **`Date` і часові пояси**: `new Date(`${dateStr}T00:00:00`)` (без
  `"Z"`) парситься як ЛОКАЛЬНИЙ час; `.toISOString()` завжди
  повертає UTC. Мішати їх для дат (не часових міток) — зсуває дату
  на день у часових поясах з позитивним зсувом (Київ). Для
  дата-рядків на клієнті — `toLocalDateString()`
  (`getFullYear/getMonth/getDate`, не `.toISOString().slice(0,10)`).
  На сервері (Edge Functions, Deno, UTC) — явний `Z`-суфікс і
  UTC-методи (`_shared/dateHelpers.ts`).
- **`!falsy` замість `== null`**: `0` — легітиме значення
  (`recurrence_window_days: 0`). `if (!value)` для «чи задано» —
  завжди `if (value == null)`.
- **CSS flex `margin-left: auto` на КІЛЬКОХ елементах одного рядка**:
  браузер ділить залишок місця ПОРІВНУ між усіма такими краями, не
  збирає в один відступ. Лише ОДИН елемент на «групу відступу».
- **`body { height: 100% }` проти `min-height: 100%`** у флекс-рядку
  з `position: sticky` елементом (бічна панель): суворий `height`
  затискає контейнер рівно у висоту вікна — sticky-елементу нема де
  «лишатись прилиплим» довше першого екрана.
- **`[hidden]` і специфічність CSS**: будь-який елемент з власним
  `display` у стилях компонента потребує явного
  `.foo[hidden] { display: none; }` — інакше атрибут `[hidden]`
  мовчки програє авторському правилу.

## Перевірка перед комітом

Локального білда/лінтера немає (стек мінімальний). Перевіряти
живим переглядом (`python3 scripts/serve.py`,
`localhost:4173`) і читанням коду; коміти — логічними, невеликими
кроками (одна дія користувача = один коміт чи невелика група
комітів), повідомлення — тим самим стилем, що вже є в git-історії
(українською, з поясненням «чому», не лише «що»).
